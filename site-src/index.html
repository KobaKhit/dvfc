Write a dashboard as YAML. Get linked, interactive charts.

dvfc turns small chart and dash spec files into browser dashboards with crossfiltering built in. Queries run on DuckDB inside the page, so there is nothing to deploy and nothing to host but static files.

How it works

Three steps from a spec file to a shipped dashboard.

1

Describe the charts

Point each chart at a CSV, Parquet, SQL query, or dbt model. Pick a type and map fields to x, y, and color.

2

Wire the interaction

One chart publishes a brush selection. Others subscribe with filterBy. That is the whole crossfilter setup.

3

Validate, then build

dvfc validate checks schema, wiring, and data refs. dvfc build emits a static site, SVG, PNG, or a single HTML file.

showcase.dash.yaml Full source 
data:
  - id: worlds
    type: csv
    path: exoplanets.csv

charts:
  - id: discovery_timeline
    type: line
    dataSource: worlds
    encoding:
      x: { field: discovery_year, type: ordinal }
      y: { field: planet, aggregate: count }
    interaction:
      brush: true
      publishes: era

  - id: habitability_scatter
    type: scatter
    dataSource: worlds
    encoding:
      x: { field: equilibrium_k }
      y: { field: habitability_score }
    interaction:
      filterBy: era

Why a text file

  • Reviewable. Dashboards go through the same pull request as the models they read from.
  • Portable. The same file drives the interactive build, the SVG export, and the MCP tools.
  • Safe for agents. A coding agent can draft a dash, and you can read every line before it ships.
  • Small. No plugin system to learn first. Thirteen chart types, one encoding model.

What is inside

Proven pieces, assembled so you do not have to.

01

Mosaic coordination

Linked selections come from UW Mosaic. Brush one chart and every subscriber requeries, the way dc.js and crossfilter worked, on a modern engine.

02

DuckDB in the browser

Aggregation and filtering happen in DuckDB-WASM. Ship the output folder to GitHub Pages, S3, or an internal wiki. No API, no database server.

03

dbt-aware resolution

Reference a model by name. dvfc reads manifest.json, finds the table, and fails validation early if the ref is missing.

04

Tools for coding agents

An MCP server exposes validate, search, get, and render. Agents work in the same files you review, with the same checks.

Validation

Broken charts fail in CI, not in front of readers.

dvfc validate checks the JSON Schema, confirms every filterBy has a publisher, and verifies that referenced data exists. Run it on every pull request. 

pnpm exec dvfc validate examples/sales-board/sales.dash.yaml
pnpm exec dvfc preview  examples/sales-board/sales.dash.yaml
pnpm exec dvfc build    examples/charts/revenue_trend.chart.yaml -f svg
