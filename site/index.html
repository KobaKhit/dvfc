Build a crossfiltered dashboard with dvfc. Start with: git clone https://github.com/KobaKhit/dvfc.git && cd dvfc && pnpm install && pnpm build
sales.dash.yaml Source ↓ 
id: sales-board
title: "Sales & Flights Analytics"
coordination:
  auto: true

data:
  - id: sales_daily
    type: dbt
    model: sales_daily

charts:
  - id: sales_trend
    type: line
    dataSource: sales_daily
    encoding:
      x: { field: date, type: temporal }
      y: { field: sales, aggregate: sum }
    interaction:
      brush: true
      selection: salesBrush

  - id: sales_by_region
    type: bar
    dataSource: sales_daily
    encoding:
      x: { field: region, type: nominal }
      y: { field: sales, aggregate: sum }
    interaction:
      filterBy: salesBrush  # linked

The open-source language

Every dashboard should show its work.

Data refs, encodings, and selection wiring live in one text file. People and agents read, edit, and review the same board — then Mosaic makes it interactive in the browser.

Declare the links

Brush sources publish a selection; other charts subscribe. No custom filter engine.

# brush source
interaction:
  brush: true
  selection: dateBrush

# linked chart
interaction:
  filterBy: dateBrush

What you get

  • Native crossfiltering — Mosaic coordination, not a screenshot of charts.
  • In-browser SQL — DuckDB-WASM. Ship a static HTML bundle.
  • dbt-friendly inputs — Resolve models from manifest.json.
  • Agent tooling — CLI + MCP to validate, search, compose, and build.

Validation

Confidence should ship with every change.

Validate board structure before anyone brushes a broken chart. Schema, semantics, and dbt refs fail on the branch — not in the browser.

✓ All checks have passed
dvfc validate *.dash.yaml / *.chart.yaml

One command

JSON Schema + semantic wiring + data existence.

Why Mosaic

Interaction is the product.

Reports are useful. Linked brushing is how analysts think. dvfc compiles YAML into Mosaic so every board is explorable out of the box.
